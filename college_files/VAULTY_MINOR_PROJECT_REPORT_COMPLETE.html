CHAPTER 1: INTRODUCTION
1.1 Introduction

In recent years, the digital economy has witnessed an unprecedented transformation from one-time asset ownership to recurring, service-based subscription models. Consumers, particularly college students, young professionals, and digital-first individuals, regularly subscribe to multiple online services across digital entertainment (e.g., Netflix, Spotify, Prime Video), cloud productivity (e.g., Google One, iCloud), artificial intelligence tools (e.g., ChatGPT Plus, Claude Pro), and health and lifestyle platforms (e.g., Cult.fit).

While subscriptions offer continuous access to software and media without large upfront capital, they create a significant personal finance challenge known as "subscription bleed." Because recurring debits occur automatically via Unified Payments Interface (UPI) autopay mandates, credit cards, or net banking, individuals frequently lose visibility over the total amount deducted on a monthly or annual basis. Furthermore, users frequently enroll in promotional zero-cost trial periods that automatically convert to costly recurring plans without explicit pre-debit confirmations.

Vaulty is developed as a focused, lightweight, and intelligent personal subscription tracking and renewal management web application. Designed specifically to solve this problem, Vaulty aggregates all recurring liabilities onto a unified dashboard, normalizes varying billing cycles into a clear monthly "burn rate," detects neglected or unused subscriptions ("zombie subscriptions"), and provides an interactive radar to alert users before promotional trials convert into unwanted debits.

1.2 Advantage

The Vaulty platform provides several distinct practical and technical advantages over traditional personal finance management methods such as generic spreadsheets or manual diary entries:

  • Normalized Spend Metrics: Different services bill along varied periodic intervals—weekly, monthly, quarterly, and annually. Vaulty automatically normalizes all payment intervals into a standard Monthly Wallet Bleed figure using verified mathematical formulas.
  • Automated Zombie Detection: The system continuously monitors user activity intervals. Active subscriptions that have not recorded usage for over 30 days are automatically flagged as "zombies," highlighting immediate potential monthly savings.
  • Trial Trap Radar: Promotional free trials are tracked with strict countdown timers. Critical alerts trigger within 48 hours of trial expiry, allowing users to make an informed cancellation decision before auto-debit occurs.
  • Zero Bank Credential Exposure: Unlike aggressive financial aggregators that demand bank credentials or SMS read permissions, Vaulty is built on a privacy-first model where the user retains complete control over their recorded financial profiles.
  • Dual Persistence Mode: Vaulty features a robust repository architecture that supports both cloud-synced persistent storage (Supabase PostgreSQL with Row Level Security) and an offline-first browser demonstration mode using localStorage.

  • Notification System: In-app alerts warning of trials expiring within 7 days (urgent warning at ≤ 48 hours) and standard renewals within user-configured reminder windows.

Out of Scope: Real-time automated bank API scrapping and programmatic auto-cancellation on third-party merchant servers (due to banking API constraints and regulatory compliance).

1.5 Applications

  • College Students & Young Professionals: Managing discretionary spending across video streaming, music, AI tools, and gaming platforms.
  • Freelancers & Independent Creators: Tracking recurring software-as-a-service (SaaS) expenses such as cloud storage, domain renewals, design suites, and developer APIs.
  • Household Budgeters: Maintaining a centralized record of shared family subscriptions, broadband utilities, and gym memberships.
1.6 Conclusion

Vaulty bridges the gap between complex, invasive budgeting platforms and tedious manual spreadsheets. By combining strict computational accuracy with a modern, high-contrast user interface, the project provides an accessible, secure, and actionable financial utility that effectively curbs recurring financial waste.

CHAPTER 2: LITERATURE REVIEW
2.1 Evolution of Subscription and Recurring Expense Tracking

Over the past two decades, personal financial accounting has evolved through several distinct paradigms:

  • Manual Physical Ledgers (Pre-Digital Era): Historically, household budgeting relied on physical register books, cash envelopes, and handwritten expense sheets. While effective for localized cash transactions, this methodology lacks automation, offers zero foresight into future recurring debits, and completely fails to scale in modern digital transaction environments.
  • Spreadsheet-Based Tracking (Excel & Google Sheets): In the early 2000s, spreadsheet software became the standard digital alternative for budget tracking. Spreadsheets provide computational flexibility through custom formulas (SUM, VLOOKUP). However, user research reveals major friction points: manual entry is time-consuming, spreadsheet mobile experiences are clunky, formulas frequently break when modifying rows, and spreadsheets lack real-time date calculation mechanisms to roll forward renewals or alert users about expiring trials.
  • Automated Banking Aggregators: Over the last decade, fintech solutions emerged that connect directly to banking APIs via Open Banking frameworks or SMS scraping. While automated, these applications exhibit severe security and privacy drawbacks. Users are increasingly uncomfortable granting third-party access to their primary bank accounts or personal text messages. Furthermore, banking aggregators reflect debits after they have already cleared the account, providing retrospective accounting rather than proactive prevention of unwanted renewals.

This historical trajectory underscores a critical requirement: consumers need an automated tracking tool that provides forward-looking visibility without requiring intrusive banking access.

11
2.2 Shift Towards User-Centric Spend Intelligence Systems

Recent academic literature and industry analyses emphasize a shift toward "Spend Intelligence" rather than mere expense logging. Research demonstrates that the psychological phenomenon known as "subscription blindness" occurs when micro-payments (e.g., ₹149, ₹299, ₹649) recur silently in the background. Because each debit appears relatively modest in isolation, consumers fail to realize their cumulative monthly financial impact.

A critical requirement identified in modern financial software is normalized burn-rate visibility. Users require a single, unpolluted number representing their active monthly commitments, irrespective of whether individual plans bill weekly, monthly, quarterly, or annually. Additionally, consumer advocacy studies highlight the "Trial Trap"—a business model wherein service providers rely on user forgetfulness to convert promotional free trials into full-priced ongoing liabilities. An effective software solution must prioritize proactive reminders over post-facto balance sheets.

2.3 Role of Modern Web Technologies and Client-Side Computation

The development of modern component-driven web frameworks has fundamentally reshaped how financial dashboards are built. Several key technological transitions informed the design of Vaulty:

  • Next.js 14 & React Server Components (RSC): Modern web applications can now blend server-side rendering for instant page loading with client-side reactivity for real-time data filtering. By computing analytics and mathematical transformations using pure functional TypeScript modules, applications eliminate unnecessary network latency.
  • Component-Driven Declarative UI (Tailwind CSS): Historically, rich financial dashboards were burdened by heavy CSS frameworks that slowed down initial render times. Tailwind CSS enables utility-first styling with minimal CSS bundles, allowing responsive, high-contrast user interfaces with sub-second First Contentful Paint (FCP).
  • Decoupled Relational Backends (Supabase & PostgreSQL): Cloud-hosted PostgreSQL with Row Level Security (RLS) offers enterprise-grade authorization at the database layer. Every database row is linked directly to an authenticated user ID (auth.uid()), ensuring that user financial records are cryptographically insulated without requiring heavy intermediate application servers.

CHAPTER 3: DESIGN OF PROJECT MODEL
3.1 System Design

The design of Vaulty is grounded in modular, decoupled software engineering principles. The primary design objective is to provide instant computational responsiveness while preserving strict data integrity and privacy.

The system is structured around three core operational layers:

  1. The User Interaction & Presentation Layer: Responsible for rendering interactive visual dashboards, providing intuitive data entry forms, handling client-side filtering, and presenting responsive charts.
  2. The Computational & Logic Engine: Implemented as a set of pure TypeScript functions (lib/calc.ts and lib/alerts.ts). This layer handles all domain logic independently of the UI framework or database provider, guaranteeing reproducibility and facilitating automated testing.
  3. The Data Abstraction Layer: Governed by the Repository Pattern. An abstract interface (SubscriptionRepository) decouples application code from the concrete data source. This allows the system to seamlessly switch between cloud-synced PostgreSQL (via Supabase) and browser-local persistence (localStorage) without changing component code.
3.2 Architecture of the Proposed System

Vaulty adopts a modern 3-Tier Architecture specifically tailored for Next.js 14 App Router applications. The architecture separates user presentation, application logic, and data persistence into cleanly defined boundaries.

3.3 Working of the System

The operational lifecycle of Vaulty follows a structured, deterministic flow:

  • 1. Session Initialization: On arrival, the system checks user authentication. If authenticated via Supabase, cloud records are fetched. If the user selects "Continue as demo user", the system initializes LocalRepository, loading Arjun's benchmark profile into localStorage.
  • 2. Subscription Entry & Presets: Selecting a brand preset (e.g., Netflix, Spotify, Claude Pro) auto-populates the service name, category, accent color, and official cancellation portal URL. The user enters cost, billing cycle (Weekly, Monthly, Quarterly, Yearly), and trial parameters.
  • 3. Mathematical Normalization: Costs are normalized to a standard 30-day equivalent: Weekly ($ ext{Cost} imes 52 / 12$), Quarterly ($ ext{Cost} / 3$), and Yearly ($ ext{Cost} / 12$). Paused and cancelled subscriptions are excluded from spend totals.
  • 4. Intelligence Scans: Subscriptions with inactivity ≥ 30 days are flagged as zombies. Expiring trials under 7 days trigger warning pills on the Trial Radar. Expired renewal dates automatically roll forward.

4.3 Testing of the System (Unit & Boundary Tests)

Automated unit test suites were implemented in tests/calc.test.ts to rigorously evaluate all boundary conditions within lib/calc.ts:

  • Cycle Normalization Tests: Verified ₹100/week converts to (100 × 52) / 12 = ₹433.33/mo; ₹900/quarter converts to 900 / 3 = ₹300.00/mo; ₹1,200/year converts to 1,200 / 12 = ₹100.00/mo.

  • Zero-Division Handling: Evaluated percentChange logic when the previous month's expenditure equals zero, confirming safe fallback without runtime exceptions (NaN or Infinity).

5.5 Subscription Tracking & Alert Process

The Bleed Radar (/radar) implements automated intelligence scans:

  • Trial Conversion Watch: Flags trials ending within 7 days, elevating urgency to high-priority pink styling when ≤ 48 hours remain.

6.3 Subscription & Alert Records Management

Each table is defined with precise check constraints and foreign key relationships:

  • profiles: Extends Supabase auth.users. Stores user display names, preferred reporting currency (default INR), and reminder intervals.
  • categories: Contains normalized category definitions (Streaming, Gym/Health, Cloud, Gaming, AI Tools, Utilities, Other) with dedicated hex color codes.
  • subscriptions: Stores plan attributes with check constraints ensuring cost >= 0, billing_cycle IN ('weekly','monthly','quarterly','yearly'), and status IN ('active','paused','cancelled').
  • price_history: Maintains temporal pricing records, allowing the application to track price hikes across successive billing cycles.
  • alerts: Stores deduplicated, actionable notifications tagged with specific alert types (trial, renewal, zombie, price_hike).
6.4 Database Operations (CRUD & Triggers)

Automated database triggers streamline user provisioning:

create function handle_new_user() returns trigger as $$ begin insert into profiles (id, email, name) values (new.id, new.email, coalesce(new.raw_user_meta_data->>'name', split_part(new.email,'@',1))); return new; end; $$ language plpgsql security definer; create trigger on_auth_user_created after insert on auth.users for each row execute procedure handle_new_user();
6.5 Advantages of Database Integration with Row Level Security

Vaulty enforces data isolation directly within the PostgreSQL database kernel using Row Level Security (RLS):

alter table subscriptions enable row level security; create policy "Users can only access own subscriptions" on subscriptions for all using (auth.uid() = user_id);

Under this architecture, even if an unauthorized API call attempts to query or alter another user’s record, PostgreSQL rejects the transaction at the database engine level, guaranteeing total confidentiality.
